> **현재 상태 안내:** 이 문서는 활성화 전 검토 이력을 보존한다. 사용자의 구현 순서 1번 지시로 하네스와 두 룰은 2026-11-02 활성화됐다. 아래 비활성·미적용·기존 설정 오류 설명은 당시 상태이며, 최신 작업 결과는 [구현 계획](../IMPLEMENTATION_PLAN.md)을 따른다.
> **과거 검토 기록:** 아래 내용은 사용자 후속 수정·정책 변경 전의 기록이다. 계정, 첨부 5개 권고, 답변자 과거 포인트 이력 삭제 권고는 이후 요청으로 대체됐다. 현재 기준은 [재검토 결과](./FIGMA_RECHECK_2026-11-02.md)와 [최신 하네스](./PROJECT_HARNESS.md)를 따른다.

> **상태: 검토 결과 · 정책 변경/개발 적용 아님**
>
> 사용자 요청에 따라 최신 Figma를 읽고 현재 하네스와 비교했다. 이 문서의 제안은 확정 정책을 덮어쓰지 않는다. Figma 디자인, 앱 코드, 활성 개발 지침, 두 LLM 룰은 변경하지 않았다.

## 검토 범위와 결론

- [Main 페이지](https://www.figma.com/design/HOnSYZ617IM9y16qx8ZXcQ/K-A?node-id=146-206)의 화면 프레임 31개에서 텍스트·구조를 확인하고, 주요 화면 17개를 이미지로 확인했다. 텍스트 노드로 추출되지 않는 로그인 폼과 사진 선택 안내도 이미지로 확인했다.

- 기준 문서: [프로젝트 하네스](./PROJECT_HARNESS.md), [답변 평가 룰 v1](./ANSWER_EVALUATION_RULES.md), [질문 보상 책정 룰 v1](./QUESTION_REWARD_RULES.md).
- **현재 로컬 데이터/Node API 구조와 두 LLM 룰을 다시 설계할 필요는 없다. 하네스 11절의 오래된 디자인 설명을 갱신하고, 화면별 상태·이동·데이터 연결을 보완하는 것이 우선이다.**
- Figma의 정적 화면은 처리 성공·저장·클릭 동작의 구현 증거가 아니다. 이번에는 앱 실행, 실제 로그인, 외부 LLM 호출, 금전 전환을 시험하지 않았다.

## 하네스에 추가하면 개발이 명확해지는 항목

아래는 **보완 제안**이다. 기존 확정 정책의 구현을 구체화하는 항목과 기능 범위를 새로 선택하는 항목을 구분한다.

### 기존 정책의 구현을 구체화

1. **화면별 상태표와 이동 경로.** 작성 → 책정 대기 → 등록 성공/보류/실패, 답변 저장 → 평가 예약 → 결과/보류/실패, 답변 선택 → 확인 → 채택 완료를 명시한다. 취소·뒤로가기·중복 클릭·늦은 응답 처리는 두 룰을 그대로 참조한다. 성공 상태만 그려진 Figma 때문에 실패 정책을 생략하지 않는다.
2. **공유 모달 동작.** 신고/메뉴/확인 모달을 하나씩 열고, 닫을 때 원래 화면과 포커스로 돌아가게 한다. 현재 신고 프레임은 답변 등록 완료 시트도 함께 보이므로 실제 구현에서 겹쳐 띄우지 않는 흐름이 필요하다.
3. **권한별 화면 차이.** 질문 작성자의 수정·삭제·채택, 답변 작성자의 수정·허용되는 삭제, 다른 사용자의 신고·차단을 구분한다. 질문자만 점수·근거를 보고, 답변자는 저장 성공과 보상 결과를 확인한다. 차단 후 목록 이동 및 설정에서 해제하는 화면도 연결한다.
4. **빈 화면·오류 화면.** 게시글/답변이 없는 상태, 검색 결과 없음, 이미지 제한 초과, 포인트 입력 오류, 책정 기본 보상 선택, 평가 보류·실패·stale, 이미 채택된 질문을 그린다. 사용자가 글을 직접 붙여 넣는 데모이므로 첫 진입의 빈 목록이 실제 출발 상태다.
5. **데이터 표시 연결.** 홈·리워드·채택 완료·내 프로필은 각 계정의 저장 데이터만 읽는다. 원문과 UI 언어를 구분하고, 한국어 예시의 강제 줄바꿈/고정 높이를 그대로 옮기지 않는다. 네 언어의 긴 문구와 작은 화면에서 카드·시트가 늘어날 수 있어야 한다.
6. **Figma 기준 프레임 갱신.** 아래 최신 ID를 11절에 반영하고, 메뉴·직접 입력이 아직 반영되지 않았다는 과거 설명을 정리한다. 구현 직전에는 다시 해당 화면을 확인한다.

## 적용 판단

- 기존 정책 충돌은 대부분 **Figma 문구·예시 데이터·입력 상태를 확정 정책에 맞추는 일**이다. 이를 위해 보상표나 평가 룰을 새 버전으로 바꿀 이유는 없다.
- 하네스는 **디자인 참조 갱신 + 화면별 상태/이동 정의 + 부가 기능 범위 명시**를 보완하면 된다. 앱 구조 변경이나 전체 하네스 재작성은 필요하지 않다.
- 칭호·알림·인기 추천 등은 Figma에 화면이 있다는 이유만으로 자동 구현 범위에 넣지 않는다. 위 권장안으로 범위를 제한하면 현재 최우선 시연 목표를 유지할 수 있다.
- 이번 작업은 검토와 검토 문서 작성까지다. 하네스 원문, LLM 룰, 앱 코드, Figma는 수정하지 않았고 활성화도 하지 않았다.
