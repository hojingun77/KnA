# K&A Figma 수정 재확인 · 2026-11-02

> **현재 상태 안내:** 이 문서는 활성화 전 검토 이력을 보존한다. 사용자의 구현 순서 1번 지시로 하네스와 두 룰은 2026-11-02 활성화됐다. 아래 비활성·미적용·기존 설정 오류 설명은 당시 상태이며, 최신 작업 결과는 [구현 계획](../IMPLEMENTATION_PLAN.md)을 따른다.
> **최신 사용자 결정 · 보상 표시와 채택 확인:** 내부 긴급 보상은 기본액의 50% 가산을 유지하고, 사용자에게 보이는 보상 안내는 현재 Figma의 포인트 금액 표현을 유지한다. `50% 추가`라는 비율 안내로 바꾸지 않는다. 실제 질문별 결과는 계산·저장된 금액을 표시한다. 채택 확인은 `이 답변을 채택할까요?` / `채택하기` / `취소`로 통일했다. 이전 채택 문구를 우선하거나 보상 안내를 비율 문구로 수정하라는 권고는 적용하지 않는다. [최종 점검 기록](./DEVELOPMENT_READINESS_2026-11-02.md)과 하네스·두 룰 문서에 반영했으며 이번 후속 결정에서는 문서만 수정했다.

## 최신 결정 및 화면 확인 · 4차 재검토

> **이 절이 아래 3차 및 이전 검토의 미해결 표시를 대체한다.** 사용자는 이전 지적 1번인 점수 표시 문구를 현재 Figma대로 유지하기로 확정했다. 문서만 수정했으며 Figma 디자인·앱 코드는 변경하지 않았고 하네스도 활성화하지 않았다.

- **표시 문구 유지 확정:** 채택 목록·선택·확인 화면의 숫자 배지와 자동 채택 안내의 `AI 신뢰도`, 답변 등록 완료의 `AI 신뢰도 검증 결과`를 그대로 사용한다. 모든 점수 화면에 `AI 참고 점수` 또는 공통 설명을 추가하라는 이전 제안은 철회하며, 이 항목을 남은 디자인 수정 과제로 다시 제시하지 않는다. 평가 진행 화면에 이미 반영된 `답변을 검색 자료와 비교 중`·`AI 참고 점수 계산`도 유지한다.
- **현재 Figma 재확인:** Main의 화면 프레임 31개 문구·구조를 새로 읽고, 채택 목록 `539:581`·질문 등록 완료 `844:807`·답변 등록 완료 `683:423`·답변 평가 진행 `668:982`를 이미지로 확인했다. 원본 파일은 읽기만 수행했다.
- **중복 프레임 정리 확인:** 이전 등록 완료 프레임 `665:127`은 Main 목록에 없으며 직접 노드 조회도 `null`을 반환했다. 현재 기준은 [질문 등록 완료 `844:807`](https://www.figma.com/design/HOnSYZ617IM9y16qx8ZXcQ/K-A?node-id=844-807)이며, 이전 사본 정리 권고는 해결됐다.
- **질문 분석·보상 설명 확인:** `질문 입력 확인 → 답변에 필요한 정보 분석 → 리워드 포인트 책정`이 유지됐다. 등록 완료는 의료 질문·기본 100P·긴급 +50P·최종 150P이며, 응급실 비용 범위 확인이라는 리워드 판단 이유도 반영됐다. AI가 긴급 여부를 결정한다는 이전 문구는 현재 기준에 없다.
- **기존 확정사항 유지 확인:** 두 계정의 시작 잔액 1,000P, 새 채택 예시의 누적 1,150P, 답변자 월간 +400P/3회와 과거 -2,000P 내역, 전환 직접 입력 및 지정 토스트, 신고 사유 5개가 유지됐다. 150P는 여전히 화면 예시이고, 새 전환 시도는 잔액·원장·내역을 바꾸지 않는다.
- **하네스 정합성 수정:** [하네스](./PROJECT_HARNESS.md) 7.2·7.7·11·12절과 [답변 평가 룰](./ANSWER_EVALUATION_RULES.md) 1·5절에서 강제 명칭 규칙을 제거하고 표시 문구와 실제 기능을 구분했다. 하네스의 구버전 등록 완료 노드 참조와 이미 수정된 질문 분석 문구를 미확정으로 적은 설명도 갱신했다. 결과 상세의 실제 근거·이유·평가 시각은 유지한다.
- **기능 범위 유지:** 제한된 검색·기존 프롬프트·산식·출력 계약·질문자만 열람·실패/보류 시 총점 없음·명시적 mock 구분·7일 자동 채택의 유효 후보 규칙은 바꾸지 않았다. `kna-evidence-v1`과 `kna-reward-v1`을 유지한다. 향후 RAG 및 실제 모델 학습은 확장 계획이며 현재 완료된 기능이나 이번 작업의 추가 범위로 취급하지 않는다. RAG를 사용해도 근거에 없는 주장을 생성할 수 있으므로, 디자인 명칭을 정확성 보장과 동일시하지 않는다([RAGTruth, ACL 2024](https://aclanthology.org/2024.acl-long.585/)).
- **결론:** 이전 3차 검토에서 남겼던 점수 문구와 중복 프레임 두 항목은 각각 사용자 결정과 디자인 수정으로 정리됐다. 이번 확인 범위에서는 추가로 필수 수정할 Figma 문구를 발견하지 못했다. 로컬 프로토타입 개발 기준으로 사용할 수 있는 문서 상태이며, 기존 실패·보류·입력 오류·실제 평가 결과 표시 등 구현 요구는 그대로다. 문서 상태는 계속 비활성·개발 미적용이다.

> **최신 사용자 확정 · 시작 잔액 정정:** 질문자 `skyking`과 답변자 `cutetl123`은 모두 **1,000P**로 시작한다. 답변자의 과거 -2,000P 표시 내역과 최신 Figma의 월간 +400P·채택 3회는 유지한다. 이전 검토의 답변자 3,250P·월간 +1,400P/5회 해석과 잔액 미확정 메모는 더 이상 적용하지 않는다. 하네스의 시드·계정 표·원장·화면 참조·검증 예시를 모두 정정했다. 새 채택 150P를 받으면 1,150P이며, 새 전환 시도는 토스트만 표시해 잔액을 바꾸지 않는다.

## 이전 화면 확인 · 3차 재검토

> 아래는 당시의 관측·제안 기록이다. 점수 명칭 추가와 중복 프레임 정리는 위 4차 재검토에서 해결됐으므로 현재 미해결 항목이 아니다. 당시 Main 32개 프레임의 문구·좌표·겹침 순서를 읽고 핵심 4개 화면을 이미지로 확인했다. 아래쪽 구버전 프레임을 현재 수정본의 오류로 보고하지 않았다.

- **질문 분석 `724:129`: 수정 확인.** `질문에 맞는 리워드를 책정하고 있어요`, `질문 입력 확인`, `답변에 필요한 정보 분석`, `리워드 포인트 책정`으로 정리됐다. 현재 제한된 분류 기능의 설명으로 적절하다. 실제 완료 체크는 구현 시 처리 상태와 연결한다.
- **질문 등록 완료 `844:807`: 수정 확인.** 안내 문구, 카테고리 `의료`, `기본 리워드 +100P`, `긴급 +50P`, 최종 150P, `응급실 비용 범위를 확인하는 질문으로 판단해 기본 리워드 100P를 적용했어요.`가 모두 반영됐다. `+100P`는 이 카드에서 기본 보상 구성액으로 읽히므로 추가 문구 수정이 필수는 아니다. 질문 등록 시 잔액을 적립하는 동작으로 구현하지 않는다.
- **답변 평가 진행 `668:982`: 수정 확인.** `답변을 검색 자료와 비교 중`, `핵심 사실 확인`, `검색 자료와 비교`, `AI 참고 점수 계산`으로 변경됐다. 실제 기능 범위와 맞는다.
- **점수 표시 화면 `539:581`, `816:204`, `816:456`: 설명 보완 필요.** 계산 중 화면에는 참고 점수라는 명칭이 있지만 실제 점수를 읽는 화면에는 숫자 배지만 보인다. 공통 안내 또는 점수 배지 설명에 `AI 참고 점수`를 추가하면 된다. 예: `숫자는 검색 자료와 비교한 AI 참고 점수예요.` 7일 자동 채택 안내의 `AI 신뢰도`도 같은 명칭으로 맞추는 것을 권장한다. 숫자는 디자인 예시로 유지 가능하며 실제 산출값으로 대체할 예정이다.
- **중복 프레임: 정리 권장.** `665:127`은 이전 `임금 체불`·`비자`·`AI가 긴급도를 판단` 문구가 남아 있는 아래쪽 사본이다. 최신 `844:807`과 같은 좌표이며 Main 자식 순서는 각각 26·27이다. 최신본만 구현 기준으로 쓰고 구버전은 별도 보관 구역으로 이동하거나 구버전임을 표시하면 된다. 두 사본을 모두 다시 수정해야 한다는 뜻이 아니다.
- **기존 수정 유지 확인.** 150P 예시, 신고 사유 5개, 계정 시작 잔액 1,000P·새 채택 후 1,150P, 월간 +400P/3회, -2,000P 과거 내역과 지정 온누리 토스트가 유지됐다. 이전에 남아 있던 잔액 텍스트 `821:940`·`843:1917`·`843:2045`도 모두 1,000P로 바뀌었고, 미연동 문구의 체크 문자도 제거됐다.
- **이번 점검의 결론:** 핵심 AI·보상 문구 충돌은 해소됐다. 남은 작업은 결과 화면의 점수 설명과 Figma 사본 정리이며, 새 보상 정책·LLM 룰 변경은 필요하지 않다. 하네스 활성화·앱 구현·Figma 수정은 수행하지 않았다. 기존 하네스의 실패/보류/입력 오류 등 구현 요구가 없어졌다는 뜻은 아니다.

## 질문 등록 완료 문구 · 추가 확인 및 제안

- `질문_작성_흐름` 영역의 `03_질문_등록_완료` 두 프레임 `665:127`·`844:807`은 같은 좌표에 겹쳐 있다. 최신 위쪽 프레임은 [844:807](https://www.figma.com/design/HOnSYZ617IM9y16qx8ZXcQ/K-A?node-id=844-807)이다. 아래 과거 검토가 지적한 두 프레임의 차이는 이 중복 배치 때문에 화면상으로 구분하기 어렵다.
- 위쪽 수정본은 상단 안내가 `질문 내용을 분석해 기본 리워드를 정했어요. 선택한 긴급 옵션의 추가 보상을 반영했어요.`로 바뀌었고 카테고리도 `의료`다. 이 부분은 수정 확인했다.
- 남아 있는 판단 근거 `임금 체불 신고 절차와 노동 관련 법 지식이 필요해 난이도를 적정으로 판단했어요.`는 현재 응급실 비용 질문과 맞지 않는다. 현재 150P 예시의 교체 문구로 **`응급실 비용 범위를 확인하는 질문으로 판단해 기본 리워드 100P를 적용했어요.`**를 제안한다.
- 카드의 `난이도 / 보통 +100P`는 `기본 리워드 / 100P`로 정리하고, 사용자 긴급 선택에 따른 `긴급 +50P`는 별도 항목으로 유지하면 최종 150P와 일치한다. 긴급 여부를 AI가 판정했다는 문구는 쓰지 않는다.
- 위 문구는 현재 화면의 기본형 성공 예시다. 구현에서는 실제 모델의 등급·이유와 앱이 계산한 금액을 표시하며, 모든 질문을 100P나 기본형으로 고정하지 않는다. 기본 보상 대체 경로는 기존대로 `기본 보상 적용 · AI 책정 아님`을 표시한다.
- 이번에는 하네스의 시작 잔액만 확정 수정하고 문구는 제안으로 기록했다. Figma·앱 코드는 변경하지 않았고 하네스도 활성화하지 않았다.

## 최신 추가 수정 확인 · 2차 재검토

> 이 절이 아래 1차 재검토의 Figma 관측 결과를 대체한다. 하네스의 확정 정책을 바꾼 것은 아니다. Main의 화면 프레임 32개 문구·구조와 주요 화면 10개의 이미지를 확인했다. Figma와 앱 코드는 수정하지 않았다.

### 해결된 부분

- 이전에 남아 있던 채택 목록·선택·확인의 300P 배지와 신고 화면의 300P 지급 문구가 모두 150P로 바뀌었다. 이번 Main 텍스트 검사에서 `300P`는 발견되지 않았다. 다른 일반 질문의 100P 예시는 오류가 아니다.
- 신고 사유에 상업적 광고 및 판매, 욕설/비하, 유출/사칭/사기, 불법촬영물 등이 유통, 낚시/도배가 표시된다. 항목 순서·유출/사칭/사기의 나열 순서는 다르지만 확정한 5개 범주가 모두 반영됐다.
- 전환 화면은 `✓ 연동됨`에서 `✓ 연동되지 않음`으로 바뀌었다. 실제 연동 완료로 보이던 문제는 해소됐다. 새 전환은 안내 토스트만 제공하는 기존 정책을 유지한다.
- 질문 분석 제목이 `질문에 맞는 리워드를 책정하고 있어요`로 변경됐다.
- 과거 -2,000P 내역과 지정 온누리 안내 토스트는 유지됐다.

### 잔액과 하네스의 새 차이

- 홈·질문/게시판 선택·리워드·전환·전환 안내의 **실제 렌더링된 카드**는 이제 `1,000P`, `이번 달 +400P · 채택 3회`로 통일돼 있다. +150/+100/+150의 세 적립 예시와 월간 +400P/3회는 일치한다.
- 채택 완료는 `+150P`, `누적 1,150P`이므로 새 디자인의 1,000P 시작과 일관된다. 이전의 “완료 화면을 3,400P로 바꾸라”는 제안은 시작을 3,250P로 유지할 때만 해당한다. 새 디자인의 1,150P를 자체 오류로 보고하지 않는다.
- 현재 하네스에는 이전 포인트 페이지 보존 요청에 맞춘 답변자 시작 3,250P·월간 +1,400P/5회가 남아 있다. **새 디자인의 1,000P·+400P/3회를 최종 시연 기준으로 사용할지 기준 일치가 필요하다.** 이번 요청은 재검토이므로 이 금융 시연 데이터 정의를 임의로 다시 변경하지 않았다.
- 리워드 `843:2045`, 전환 `821:940`, 전환 안내 `843:1917`에는 덮여서 이미지에 보이지 않는 이전 `3,250P` 텍스트 레이어도 남아 있다. 시각 오류로 보고하지 않되, 현재 1,000P를 기준으로 정하면 중복 레이어를 삭제하면 구현 시 혼선을 줄일 수 있다.

### 선택적인 표현 정리

- `연동되지 않음` 옆 체크 표시(✓)는 성공을 연상시킬 수 있으므로 체크 없이 회색 안내로 표시하는 편이 자연스럽다. 기능 정책 문제는 아니다.
- 이름·이메일·점수 등의 예시 데이터는 실제 구현에서 확정 계정/결과를 읽으면 되며, 모든 Figma 예시를 바꾸는 일을 개발 시작의 선행 조건으로 삼지 않는다.
- 기존 룰에 있는 실패·보류·입력 오류 상태는 구현에 필요하지만, 이번 문구 검토 때문에 새 기능이나 LLM 범위를 늘리지는 않는다.

## 하네스에 반영한 결정

- 질문자: 중국인 `skyking`, 이메일 식별자 `skyhao@google.com`, 로그인 후 UI `zh-CN`. 답변자: 베트남인 `cutetl123`, 이메일 식별자 `thilinh@google.com`, UI `vi`. 사용자가 지정한 정확한 비밀번호는 하네스 7.1절의 데모 인증 정의에 반영했다. 실제 Google 로그인이나 이메일 검증은 하지 않았다.
- 사용자가 답변자 닉네임의 느낌표는 제외한다고 확인했다. 영문 ASCII 알파벳·숫자와 기존 단어 사이 공백을 허용하도록 닉네임 정책을 갱신했으며 기호는 허용하지 않는다.

- 답변자의 포인트 페이지를 Figma 상태로 유지하라는 요청에 따라 시작 잔액 3,250P·월간 +1,400P/5회·과거 표시 4개 내역을 답변자 전용 스냅샷으로 정의했다. 질문자 시작 잔액은 기존 1,000P를 유지한다.

- 위 시연 스냅샷은 실제 완전한 거래 원장이 아니다. 보이는 4개 내역 합계로 잔액/월간 요약을 역산하거나 누락된 글·실제 발급을 만들어 맞추지 않는다. 하네스 7.5절·9절에 초기값과 신규 이벤트를 구분하는 방식을 기록했다.

## AI 질문 분석: 어떤 문구가 왜 다른가

확정된 흐름은 **사용자가 카테고리·긴급 여부 선택 → LLM이 제목·본문에서 필요한 답변 작업 범위를 분류 → 앱이 등급표로 기본액을 정하고 긴급이면 50% 가산**이다. 이 단계에서는 웹 검색, 질문의 사실 검증, 자동 카테고리/언어 분류, 긴급 여부 판단을 하지 않는다. 번역도 별도 기능이다.

### 분석 진행 화면 `724:129`

| 현재 화면 문구 | 차이 | 교체 제안 · 사용자 결정 전 |
|---|---|---|
| `AI가 질문을 검증하고 있어요` | 질문이 사실인지/적절한지 검증하는 것으로 읽힌다. 지금은 보상 등급 분류다. | `질문에 맞는 리워드를 책정하고 있어요` |
| `✓ 카테고리·언어 확인` | 카테고리는 사용자가 선택하며 이 호출의 별도 입력·출력도 아니다. UI 언어는 계정 설정으로 이미 정해진다. | AI가 검사했다는 완료 단계는 제거. 필요한 경우 실제 로컬 검증에만 `질문 입력 확인` 사용 |
| `난이도와 긴급도 판단` | LLM은 답변 작업 범위만 분류한다. 긴급 선택은 모델에 보내지 않고 앱에서 처리한다. | `답변에 필요한 정보·절차 범위 분석` |
| `리워드 포인트 책정` | 결과가 앱 계산을 포함한 전체 작업이라는 뜻이라면 적절하다. | 유지 가능. 상세 단계를 보이려면 실제 상태에 맞춰 `리워드 계산` |

시간이 지나면 무조건 체크 표시가 켜지는 가짜 진행을 만들 필요는 없다. 단일 대기 문구·로딩 표시와 성공/실패 상태만으로 현재 기능을 정확히 표현할 수 있다.

### 등록 완료 화면 `665:127` 및 사본 `844:807`

현재 `AI가 난이도와 긴급도를 보고 리워드 포인트를 정했어요.`는 AI가 긴급 여부와 금액까지 결정한 것으로 읽힌다. 다음 문구를 제안한다.

> 질문 내용을 분석해 기본 리워드를 정했어요. 선택한 긴급 옵션의 추가 보상을 반영했어요.

긴급 질문 150P 예시는 다음처럼 구성하면 확정 정책과 맞는다.

- 책정된 리워드: **150P**
- 기본 리워드: **100P**
- 긴급 추가 보상: **+50P · 기본 리워드의 50%**
- 카테고리: 사용자가 실제 선택한 값
- 분류: 모델이 반환한 기본형/절차형/비교·조합형과 실제 이유

일반 질문은 긴급 추가 보상 줄을 숨기거나 0P로 표현한다. 실패 후 사용자가 기본 보상 등록을 선택한 경우에는 위 AI 성공 문구 대신 `기본 보상 적용 · AI 책정 아님`을 표시한다.

현재 등록 완료 예시에는 카테고리 `비자`와 이유의 `임금 체불 신고`도 섞여 있다. 구현에서는 서로 다른 예시를 복사하지 않고 같은 질문의 실제 선택값·분류 결과를 읽는다. `보통 +100P`를 모델이 임의로 만든 가산점처럼 쓰기보다 `기본형 100P` 또는 `기본 리워드 100P`로 구분하는 편이 명확하다.

## 이번 변경과 검증 범위

- 수정: 프로젝트 하네스의 계정·닉네임·첨부·시연 스냅샷·최신 화면 참조. 두 LLM 부속 문서는 오래된 공통 초기 잔액 문장만 하네스 참조로 정리했다.
- 유지: LLM 입력 계약, 등급표, 긴급 50%, 채점 공식, 시스템 지시문, 버전 `kna-reward-v1`·`kna-evidence-v1`.
- 이 문서의 AI 문구 교체안은 제안이다. 사용자가 결정하거나 Figma를 수정하기 전까지 새 정책으로 확정하지 않는다.
- Figma는 읽기만 수행했다. 비활성 하네스 문서만 수정했으며 앱·DB·로그인·실제 전환은 구현하거나 실행하지 않았다.
