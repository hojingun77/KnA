# K&A 로컬 프로토타입 개발 착수 최종 점검 · 2026-11-02

> **현재 상태 안내:** 이 문서는 활성화 전 검토 이력을 보존한다. 사용자의 구현 순서 1번 지시로 하네스와 두 룰은 2026-11-02 활성화됐다. 아래 비활성·미적용·기존 설정 오류 설명은 당시 상태이며, 최신 작업 결과는 [구현 계획](../IMPLEMENTATION_PLAN.md)을 따른다.
> **판정: 개발 착수 가능. 제품 정책의 추가 결정은 필요하지 않으며 아래 작은 정리 항목은 구현과 함께 처리할 수 있다.** 이 문서는 점검 기록이다. 하네스 활성화·앱 구현·Figma 수정·외부 LLM 연결을 수행한 것이 아니다.

> **후속 사용자 결정 반영:** 보상은 내부 50% 가산을 유지하되 화면에는 현재 Figma의 포인트 표현을 사용한다. 채택 확인 문구도 현재 Figma로 통일했다. 아래 두 항목은 해결됐으며, 비율 안내 교체와 이전 채택 확인 문구 유지 제안은 철회한다. 기존 코드 설정 문제는 별도 구현 작업으로 남아 있다.

> **후속 결정 이후 최종 재확인 완료:** Main 화면 31개의 문구·프레임 정보와 채택 확인·질문 등록 완료·리워드 화면 이미지를 다시 읽었다. 보상 포인트 표기와 `이 답변을 채택할까요?` / `채택하기` / `취소`가 최신 하네스와 일치하며, 개발 전에 새로 확정하거나 수정해야 할 정책 충돌은 발견하지 못했다. 현재 정책 문서의 이전 채택 문구 제거, 보상 산식·등급표·시작 잔액·룰 버전·문서 링크를 확인했다. 과거 검토의 철회된 제안은 현재 지침으로 적용하지 않는다. 앱 코드·설정이 직전 점검 이후 동일함을 확인했으므로 빌드·린트를 반복 실행하지 않았으며, 직전 빌드 성공과 기존 린트 오류 1건은 아래 기록 그대로다. Figma와 하네스 정책은 추가 변경하지 않았다.

## 확정된 표시 기준과 구현 시 처리할 항목

### 1. 보상 안내 · 사용자 결정으로 해결

- 질문 작성 `158:1951`·긴급 선택 `661:883`에는 `기본 100P / 긴급 150P`라는 일반 안내가 있다. 리워드 `843:2005` 및 전환 배경 `821:899`·`843:1877`에는 `답변이 채택되면 기본 100P, 긴급 질문은 150P가 자동 지급돼요.`가 있다.
- 사용자는 이 포인트 안내 표현을 유지하고 내부 시스템에서만 기존 긴급 50% 가산을 적용하기로 확정했다. 화면 안내를 비율 문구로 교체하라는 이전 제안은 철회한다. 개별 질문의 **150P 예시**, 과거 내역, **AI 신뢰도 문구**도 유지한다.
- 실제 질문별 등록 완료·채택 확인·지급 결과에는 계산·저장된 포인트를 표시한다. 기본 100P면 긴급 +50P·총 150P, 기본 150P면 긴급 +75P·총 225P다. 현재 디자인 안내를 모든 질문의 고정 금액 정책으로 해석하지 않는다. 하네스 7.5절과 질문 포인트 책정 룰에 반영했으며 추가 Figma 편집은 필요하지 않다.

### 2. 채택 확인 · Figma 문구로 통일 완료

- 사용자 최신 지시에 따라 Figma `816:456`의 `이 답변을 채택할까요?` / `채택하기` / `취소`로 하네스와 답변 평가 룰을 통일했다. 이전 확인 문구를 우선하라는 제안은 적용하지 않는다.
- 모달의 `채택하기`에서만 확정하고 `취소`는 상태 변경 없이 닫는다. 확정 후 취소 불가·중복 지급 방지는 유지한다. 수령자 닉네임과 지급 포인트는 선택 답변과 확정 보상에서 읽는다.

### 3. 샘플과 실제 데이터의 치환

- `Minji K.`, 일본어 `JP`, 고정 점수·게시글·답변 수 등은 디자인 예시다. 실제 구현에서는 지정 계정과 저장된 콘텐츠·평가를 표시한다. 모든 Figma 예시를 다시 편집할 필요는 없다.
- 초기 질문·답변을 시드하지 않는 기존 결정 때문에 최초 홈·게시판은 빈 상태가 필요하다. 사용자가 시연 원고를 등록하면 실제 목록으로 채운다. 네 언어의 줄바꿈, 빈 목록, 오류·평가 보류·재시도·전환 입력 오류는 구현 중 검수한다.
- 일부 카테고리 표기는 `은행/금융`, `일·알바/직장`으로 다르다. 구현에서는 최신 홈·질문 작성의 비자·주거·의료·금융·직장·교통·통신·생활 8개를 일관된 ID/번역 사전에 연결하면 된다. 현재 코드의 예전 교육·법률 분류는 그대로 이식하지 않는다.
- Google 로그인의 `Goole` 오탈자는 소셜 로그인 영역을 표현할 경우 `Google`로 정리하면 된다. 실제 소셜 로그인·가입·비밀번호 재설정과 자동 본문 번역은 기존 하네스의 범위 제외를 유지한다.

## 코드 준비 상태와 최초 구현 작업

| 실행한 검증 | 결과 |
|---|---|
| `npm run build` | 성공. 현재 스캐폴딩이 빌드됨을 확인했으며 미구현 사용자 흐름을 검증한 것은 아니다. |
| `npm run lint` | 실패 1건: `vite.config.js:9`의 `process`에 대한 `no-undef`. Node용 ESLint 환경 또는 명시적 import로 정리할 기존 설정 문제다. 이번 점검에서는 코드를 수정하지 않았다. |
| Git | `main`, 작업 트리의 기존 `docs/` 미추적 상태. 커밋·push 없음. |

하네스를 실제 적용하고 개발을 시작할 때 처리할 작업:

1. 확정 하네스와 두 룰을 활성 개발 지침에 연결하고, 기존 `.env` ignore 누락 및 위 린트 설정 오류를 정리한다. 실제 키는 서버 환경 변수에만 둔다.
2. 기존 Firebase 전제 인증 스토어를 로컬 계정 세션·IndexedDB 저장소로 연결하고 네 언어 리소스와 데이터 모델을 구현한다. Firebase·Algolia 초기화 모듈이 존재한다는 이유로 네트워크에 연결하지 않는다.
3. 로그인 → 홈 → 게시판 → 질문 작성 → 포인트 페이지를 우선 구현한다. 답변·평가·채택은 두 계정의 보조 시연 흐름으로 연결한다.
4. 외부 LLM을 붙이는 단계에서 실제 키·모델 접근·검색/구조화 출력 조합·응답 시간을 검증한다. 이번 문서/빌드 검토로 실제 API 동작까지 검증된 것은 아니다. 기존 키 미설정·실패 처리 규칙을 유지한다.

**최종 판단:** 추가 기획을 위해 개발을 미룰 필요는 없다. 보상 안내와 채택 확인 표현은 최신 사용자 결정으로 정리됐고, 남은 기존 코드 설정 수정과 실제 데이터 연결은 최초 구현 작업으로 처리한다. 별도 적용 지시가 아직 없으므로 하네스는 비활성이고 앱 개발은 시작하지 않았다.
